# 006 過去のカード通知の取り込み（バックフィル）と二重登録防止

## 目的
Gmail に溜まっている過去の三井住友カードの通知を、まとめて家計簿に取り込む。

## 変更内容
- `gas/Code.gs`: `backfillSmbcMails()` を追加。既読・未読を問わず過去の通知をすべて取り込む。進捗は `BACKFILL_OFFSET` に保存し、時間切れ（約4分）なら再実行で続きから再開する。`resetBackfill()` で進捗をリセットできる。
  - 取り込みの共通処理（`toRow_` / `postRows_` / `isTarget_`）を切り出し、新着の取り込み（`syncSmbcMails`）と共有した。
  - 店名を `normalize('NFKC')` で半角に正規化（例: `ＡＭＡＺＯＮ．ＣＯ．ＪＰ` → `AMAZON.CO.JP`）。
- `schema.sql`: `expenses` に `source_id text unique` を追加
- `migrations/005_add_source_id.sql`（新規）: 稼働中の DB へ列を追加する差分

## 設計判断
- **Gmail のメッセージ ID を source_id にして重複を無視する。** 通知はすべて未読のままなので、バックフィルと新着の取り込みが同じメールを二度処理する。ID の unique 制約と `Prefer: resolution=ignore-duplicates` で、何度実行しても二重に登録されない。
- これで、POST 成功後に既読化に失敗しても二重登録にならない（001 の残課題が解消）。
- 時刻・店名・金額の組を重複判定に使う案は採らなかった。同じ店で同額の買い物が別の機会にあると、正しい行まで消えるため。
- バックフィルは既読・未読を変更しない。新着の取り込みが後から未読分を処理しても、ID が同じなので二重にならない。
- DB への登録は GAS から行う。Gmail の取得は私の側でもできるが、Supabase の secret key をチャットに出す必要が生じるため採らなかった。

## 動作確認
- パーサーを Node で動かし、全角の店名、カンマ付き金額が期待どおり取れることを確認した。
- Gmail 上で古い通知（2026/05）を確認し、本文の書式が現行と同じであることをスニペットで確認した。ただし、全件の書式は確認していない。
- 未確認: GAS 上での実行、Supabase への一括登録、重複が実際に無視されること。パース失敗の件数はログで確かめる必要がある。

## 注意点・残課題
- 手順: Supabase で `migrations/005_add_source_id.sql` を実行 → GAS に新しい `Code.gs` を貼り直す → `backfillSmbcMails()` を実行 → ログに「完了」が出るまで繰り返す → `setupTrigger()` を実行。
- 通知は「承認照会」であり、請求の確定ではない。取り消された取引も残る。
- 通知されない利用（公共料金などの継続課金、ETC、一部の電子マネー）は取り込めない。

# 010 カテゴリの追加と月次推移タブ

## 目的
- カテゴリを画面から追加できるようにする（これまでは 10 個をコードに固定していた）。
- 月ごとの合計と、カテゴリごとの推移を、1 つのタブの中で切り替えながら比較できるようにする。

## 変更内容
- `migrations/007_custom_categories.sql`（新規）と `schema.sql`: `categories` テーブル（名前・色・並び順）、anon の select / insert、初期の 10 カテゴリ
- `lib/categories.ts`: 固定の一覧をやめ、型 `Category`、既定値（DB を読めないときの代替）、色の自動割り当て、色の引き当て関数に変更
- `components/ExpenseApp.tsx`: カテゴリを DB から取得、入力フォームに「＋カテゴリ」（名前を入れて作成）、3 つ目のタブ「月次推移」
- `components/AnalysisTab.tsx`: 色を固定の表ではなく、受け取った関数から引くように変更
- `components/TrendTab.tsx`（新規）: 月次推移

## 設計判断
- **カテゴリは追加のみにした。** 名前の変更と削除は、既存の履歴や分類ルール（`category_rules`）の文字列と食い違うため、今回は対象外にした。
- **`expenses.category` は文字列のままにした。** 外部キーを張ると、過去の `趣味`・`固定費` などの行が壊れるため。
- **追加したカテゴリの色は自動で割り当てる。** 既存の色と被らないものを順に選び、DB に保存する。
- **推移は 1 本の切り替え行にまとめた。** 先頭の「合計」と各カテゴリのチップを同じ列に並べ、タップで棒グラフ・凡例・数値の一覧が切り替わる。
  - 「合計」のときは、カテゴリの色で積み上げた棒にする（内訳も見える）。
  - カテゴリを選ぶと、そのカテゴリだけの棒になる。
- **12 か月ぶんを一度だけ取得する。** 切り替え（合計・カテゴリ・6か月/12か月）では再取得せず、取得済みのデータから計算し直す。そのため待ち時間が出ない。1000 件を超える場合に備えて、ページ分けして全件を取る。
- 棒の高さの基準は、合計の表示ではプラスの支出の積み上げ、カテゴリの表示ではその値にした。返品などでマイナスの月は、棒を 0 とし、数値は金額のまま出す。
- 前月との差は、期間の最初の月だけ「—」にした（それより前の月を取得していないため）。

## 注意点・残課題
- 手順: Supabase の SQL Editor で `migrations/007_custom_categories.sql` を実行する。実行前でも、アプリは既定の 10 カテゴリで動く。ただし、カテゴリの追加はエラーになる。
- 追加したカテゴリには、分類ルール（店名のキーワード）は付かない。履歴の行でカテゴリを選ぶと、その店名のルールとして保存される。
- 月は端末の時刻（日本時間）で区切る。

# 001 初期実装: 三井住友カード自動連携 + 手入力 PWA 家計簿

## 目的
三井住友カードの利用通知メールを自動で家計簿に蓄積し、PayPay・現金は手入力できる PWA を作る。

## 変更内容
- `schema.sql`: `expenses` テーブル、`used_at` のインデックス、RLS（この時点では anon に全操作を許可）
- `gas/Code.gs`: Gmail の未読通知をパースして Supabase に POST し、成功したら既読にする。10 分おきのトリガー登録関数つき
- `app/page.tsx`: 今月の合計、手入力フォーム、履歴一覧（`[自動]`/`[手入力]` バッジ）、削除
- `app/layout.tsx`, `public/manifest.json`, `app/pwa-icon/[size]/route.tsx`: PWA 設定とアイコン生成
- `lib/supabase.ts`: Supabase クライアントと型
- Next.js 15 / Tailwind 3 / lucide-react の設定一式

## 設計判断
- 認証なしの anon キー運用にした。個人利用で最小構成にするため。公開の危険は 002 で解消する。
- メールのパースは正規表現で行う。実メール（送信元 `statement@vpass.ne.jp`、項目 `◇利用日：` `◇利用先：` `◇利用金額：`）に合わせて修正済み。依頼文の想定（`mail.smbc-card.com`、`利用日時：`）とは違っていた。
- 失敗したメールは未読のまま残し、次回の実行で再試行する。

## 動作確認
- `next build` が通ることを確認した。
- Gmail 上の実メールを取得し、同じ形式の本文でパーサーを Node で動かして、日時・利用先・金額（カンマ付き含む）が取れることを確認した。
- 未確認: GAS 上での実行、Supabase への実際の書き込み、ブラウザ・実機での表示。

## 注意点・残課題
- メールは「承認照会に基づく通知」で、請求の確定ではない。取り消された取引も残る。
- POST 成功後に既読化へ失敗すると二重登録になりうる。
- 認証がないため、キーを知る人は全件読み書きできる（002 で対応）。

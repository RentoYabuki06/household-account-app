# 007 返品（マイナス金額）の通知に対応

## 目的
バックフィルの実行ログで、「返品」の通知がパース失敗になっていた。返品も家計簿に含めるため、マイナスの金額を読めるようにする。

## 変更内容
- `gas/Code.gs`: 利用金額の正規表現にマイナス記号（`-`、`−`、`－`）を許可
- `components/ExpenseApp.tsx`: 金額の表示をマイナスに対応（`-¥24,200`）

## 原因
返品の通知は `◇利用取引：返品` / `◇利用金額：-24,200円` の形で届く。正規表現が数字とカンマしか許していなかったため、金額が取れずに失敗していた。実行ログで失敗した4件（2026/07/20、07/25、08/05、09/04）のうち、本文を確認した3件が返品だった。残り1件（2026/07/20）の本文は未確認。

## 設計判断
- マイナスのまま保存する。`amount` は integer でマイナスを許し、今月の合計も単純な足し算で返品分が引かれる。
- 取引の種別（買物・返品）の列は追加していない。金額の符号で区別できるため。

## 動作確認
- パーサーを Node で動かし、`-24,200円`、`-7,500円` がそれぞれ `-24200`、`-7500` になることを確認した。買物（`450円`）も従来どおり取れる。
- 未確認: GAS 上での再実行、画面でのマイナス表示。

## 注意点・残課題
- バックフィルの進捗（`BACKFILL_OFFSET`）は、失敗した通知を飛ばして進んでいる。そのため、先に `resetBackfill()` を実行して進捗を戻してから、`backfillSmbcMails()` を再実行すること。登録済みの分は `source_id` で無視される。
- 2026/07/20 の1件は返品かどうか未確認。再実行後もログに残れば、本文を確認する。

# 016 レシート撮影の画面（読み取り結果をフォームに反映）

## 目的
スマホで撮影したレシートを読み取り、入力フォームに自動で埋める。間違いは、利用者が画面で直してから保存する。

## 変更内容
- `components/ReceiptScanner.tsx`（新規）: 「レシートを撮影して自動入力」ボタン（カメラを起動）、写真の縮小、合言葉の入力、`/api/receipt` の呼び出し
- `components/ExpenseApp.tsx`: 読み取り結果をフォーム（金額・店名・日付・決済手段・カテゴリ）に反映、撮影した写真のサムネイル表示、読み取れなかった項目や注意の表示

## 設計判断
- **保存はしない。** 読み取り結果は、フォームに入れるだけにした。利用者が写真と見比べて、直してから「追加」を押す。間違いに気づかないまま登録されることを避ける。
- **写真は端末で縮小してから送る。** 長辺 1600px の JPEG（1.4MB 以下）にする。読み取りには十分で、通信量とサーバーの上限（1.5MB）に収まる。向きの情報（EXIF）は反映する。
- **合言葉は、成功したときだけ端末に覚えさせる。** `localStorage` に保存し、次回からは入力不要。サーバーに拒否されたら（401）消して、もう一度聞く。
- **カード払いのレシートには警告を出す。** 三井住友カードで払うと、Gmail の自動取り込みと二重になるため。決済手段は「その他」にして、追加しないよう注意書きを出す。
- 日付を手で直したら、読み取った時刻は使わない（日付と時刻の食い違いを避ける）。
- 読み取れなかった項目（金額・店名・日付）は、注意書きで知らせ、空欄のままにする。
- 撮影した写真は、サムネイル表示のためだけに端末のメモリに持つ。サーバーには保存しない（Gemini には、読み取りのために送る）。

## 動作確認
- `next build` が通ることを確認した。
- 偽の Gemini・Supabase を手元で立てて、実際のブラウザ（Chrome）で `next dev` の画面を操作した。
  - 写真（ブラウザ内で作った画像）を選ぶと、合言葉の入力欄が出る
  - 合言葉を入れて Enter で送ると、縮小・送信され、金額（3170）、店名、日付（2026/11/10）、カテゴリ、決済手段が入力欄に入る
  - サムネイルとカード払いの警告が出る
- 未確認: スマホ実機のカメラ起動（`capture="environment"`）、iPhone の HEIC 写真の縮小、実際の Gemini での読み取り精度、ホーム画面アプリでの動作。

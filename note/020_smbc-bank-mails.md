# 020 三井住友銀行の通知メールの取り込みと、手入力の支払い方法欄の削除

## 目的
三井住友銀行の入出金の通知メールも Gmail に届くので、家計簿に取り込む。PayPay は手入力をやめ、銀行からの PayPay チャージを支出として数える。

## 変更内容
- `gas/Code.gs`: 取り込み対象を `SOURCES`（card / bankWithdraw / bankDebit）にまとめ、同じ処理で扱うようにした。
  - `bankWithdraw`: 「口座出金のお知らせ」。PAYPAY・ペイペイは店名「PayPayチャージ」、`カード …`（キャッシュカードでの出金）は「ATM出金」にする。
  - `bankDebit`: 「口座引き落としの事前お知らせ」。明細ごとに 1 行。引落予定日の 0 時（JST）を日付にする。三井住友カードの代金（`ミツイスミトモカード`）は除く。
  - バックフィルの進捗は種類ごと（`BACKFILL_OFFSET_<name>`）に持つ。`resetBackfill()` は旧形式の `BACKFILL_OFFSET` も消す。
- `migrations/009_smbc_bank.sql`、`schema.sql`: 支払い方法に「三井住友銀行」を追加。カテゴリ「水道光熱費」と、その自動分類ルールを追加。
- `lib/supabase.ts`: `PaymentMethod` に「三井住友銀行」を追加。
- `components/ExpenseApp.tsx`、`components/AnalysisTab.tsx`: 手入力の支払い方法の選択を削除。手入力の行は支払い方法を「その他」で保存する。レシート読み取りの支払い方法の反映も削除（クレジットカードの警告は残した）。
- `README.md`: 取り込み対象と手入力の説明を更新。

## 設計判断
- 金額が本文にあるのは「口座出金のお知らせ」と「口座引き落としの事前お知らせ」だけ。振込入金・振込受付・ことら送金の通知には金額がないので取り込めない（給与などの収入は取り込めない）。
- 合計・分析に含める範囲は、ユーザーの指示どおり。PayPay チャージと ATM 出金は支出に含める。水道料やローン（オリコ、APアプラス）の引き落としも含める。三井住友カード代金は、カード利用通知と二重になるので取り込まない。
- 他社カード（楽天カードサービス、(カ)ジエーシービー、セゾン）の引き落としは取り込む。アプリ内に明細がなく、二重にならないため。取り込みたくなければ `SKIP_DEBIT_PATTERN` に足す。これは指示にない判断なので、変えてほしければ言ってほしい。
- 引き落としは「事前お知らせ」から取る。実際に引き落とされた通知は届かないため。残高不足で引き落とせなかったときの「引き落とし未済」は取り込まない（事前お知らせで計上済みで、実際に失敗したかどうかは見ていない）。
- 引き落としの `source_id` は Gmail の ID ではなく、日付・内容・金額から作る（同じ内容の事前お知らせが複数回届いても二重にならない）。同一メール内に同じ内容・金額が複数あるときだけ連番で区別する。
- 出金通知の `source_id` は Gmail の ID。同じ日に同額の PayPay チャージが 2 回あっても別メールなので別の行になる。
- PayPay チャージや ATM 出金のカテゴリは未分類で入る。履歴で一度カテゴリを選べば、店名のルールとして保存され、以後同じ店名はそのカテゴリになる（既存の仕組み）。
- 手入力の支払い方法は、列を消さず「その他」で保存した。DB の制約や過去の行を変えずに済むため。

## 動作確認
- `npx tsc --noEmit` と `npm run build` が通ることを確認した。
- GAS のパーサーを Node で動かし、実メールの形式（PAYPAY・ペイペイ・キャッシュカード出金、複数明細の事前お知らせ、カード代金のみ・混在、壊れた本文）で期待どおりの行になることを確認した。既存のカード通知のパーサーも変わらず動く。
- Gmail 上で、出金通知（2025/05〜2026/11）と事前お知らせ（2025/03〜2026/10）の本文形式を確認した。全件は確認していない。

## 注意点・残課題
- 手順: Supabase で `migrations/009_smbc_bank.sql` を実行 → GAS に新しい `Code.gs` を貼り直す → `resetBackfill()` → `backfillSmbcMails()` を「完了」が出るまで繰り返す。
  - カードの通知は取り込み済みなので、重複は `source_id` で無視される。
- **過去に手入力した PayPay・現金の支出と、銀行の PayPay チャージ・ATM 出金は二重になる。** 銀行通知は 2025/05 から届いているため、バックフィル後は過去の月も二重に数える。手入力した PayPay・現金の行は、必要に応じて履歴から消してほしい。
- PayPay・現金で実際に何に使ったかは分からなくなる（チャージ・出金の時点で支出に数える）。
- 引き落としの日付は予定日で、実際の日とずれることがある。

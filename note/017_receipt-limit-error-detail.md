# 017 回数の確認に失敗したときの、エラーの種類の表示

## 目的
本番で「回数の確認に失敗しました」と出たとき、原因が画面から分からなかった。切り分けできるように、エラーの種類（コード）を表示し、サーバーのログにも残す。

## 変更内容
- `app/api/receipt/route.ts`: 回数の確認（`consume_receipt_scan`）が失敗したとき、メッセージの末尾にエラーコードを付ける。サーバーのログにも、コードと内容を出す。

## 設計判断
- 表示するのは、合言葉の確認を通ったあとの応答だけ。コードとメッセージの先頭 40 文字までで、キーなどの秘密情報は含まれない。

## 想定される原因（コードの目安）
- `PGRST202`: 関数が見つからない（`migrations/008_receipt_scan_limit.sql` を Supabase で実行していない）
- `42501`: 実行権限がない（008 の `grant` が反映されていない）
- 401 や「Invalid API key」系: `SUPABASE_SERVICE_ROLE_KEY` の値の誤り（貼り付けのミス、空白の混入など）

## 動作確認
- `next build` が通ることを確認した。
- 未確認: 本番での実際のエラーコード（原因は、この表示が出てから確定する）。
